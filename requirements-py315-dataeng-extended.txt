# Extended data-engineering stack — Python 3.15 validation lab
#
# Purpose:
#   Pin the extended (non-core) packages exercised by the compatibility
#   report so that validation coverage survives a venv rebuild.
#
# Background (see docs/KNOWN_ISSUES.md, issues ENV-001 and ENV-002):
#   The 3.15.0b2 cycle tested these packages, but they were installed ad hoc
#   and never pinned. Rebuilding the venv for 3.15.0b4 dropped them, and they
#   silently degraded to SKIP "not installed", inflating the readiness score.
#
#   The b2-recorded versions turned out to be MUTUALLY UNSATISFIABLE:
#     apache-airflow==3.2.2 -> apache-airflow-task-sdk==1.2.2 -> packaging>=25.0
#     mlflow==2.16.2        -> mlflow-skinny==2.16.2          -> packaging<25
#   No resolver can satisfy both, which means the b2 environment was built by
#   incremental installs that left at least one package's constraints violated.
#   See ENV-002 — historical results from that environment are suspect.
#
#   Versions below are a mutually consistent set resolved against Python 3.15.
#   dask was resolved on 2026-07-21 and prefect was re-pinned on 2026-10-27
#   (see the prefect note below). They are deliberately NOT the b2 versions.
#
# Usage:
#   uv pip install -r requirements-py315-build.txt
#   uv pip install -r requirements-py315-dataeng-jupyter.txt
#   uv pip install -r requirements-py315-dataeng-extended.txt
#
#   Use `uv pip install -r`, NOT `uv pip sync`. Sync enforces a single file
#   exactly and will uninstall everything not listed in it.
#
#   After a successful install, verify no constraints were violated:
#     uv pip check
#
# Not pinned here, and why (retested 2026-10-27 on Python 3.15.2; evidence in
# reports/3.15.2/READINESS_RECONCILIATION_2026-10-27.md):
#   ray      -> RAY-001, no cp315 wheel (ray 2.59.0 publishes cp310-cp314 only).
#   mlflow   -> MLF-001, every release from 3.15.0 caps pyarrow<26 and pyarrow
#               25.x has no cp315 wheel; pyarrow 26.0.0 (which has one) is
#               excluded by that cap. The older pandas<3 conflict recorded in
#               MLF-001 was not rechecked. Test mlflow in a separate venv.
#   airflow  -> installs and runs a DAG on 3.15.2 in a separate isolated env
#               (apache-airflow 3.3.2; libcst 1.9.0 installed without the pyo3
#               build failure recorded in PYO3-001; PyYAML builds from source,
#               so a binary-only install policy fails). Not pinned here to keep
#               this environment small.
#
# pyarrow is no longer blocked: cp315 wheels exist since 3.15.0 and it is part
# of the core stack (requirements-py315-core-3.15.2.lock.txt).
# pyspark is validated via Docker (pyarrow-dataeng:py3152), not installed into
# this venv, so it is not pinned here.
#
# prefect: 3.7.x is unusable on a current resolve. It requires starlette>=1.0.1
# but calls Body(..., min_items=1), which FastAPI 0.162.0 rejects, and an older
# FastAPI (0.115.12 in a dry run) cannot satisfy starlette>=1.0.1. 3.9.0
# resolves with FastAPI 0.150.0 and passed the flow, task and retry checks.
# See PRE-001 in docs/KNOWN_ISSUES.md.
#
# The exact validated set (127 packages) is in
# requirements-py315-extended-3.15.2.lock.txt.
#
# Install these one at a time. uv installs atomically, so a single build
# failure rolls back the entire transaction - including packages that would
# otherwise have succeeded.

dask==2026.7.1
prefect==3.9.0
